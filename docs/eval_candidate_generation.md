# RAG Evaluation Dataset P1 代码审查报告

基线为 `codex/eval-corpus-export-v1` 的 `9686e39`。入口
`generate-eval-candidates` 从明确授权范围内的快照生成待审核候选。生成器只读
本地快照，按文档和相同的 Chunk 标签分批。每条候选保留快照的完整
`scope`。其中 `chunk_permission_tags` 只描述来源 Chunk，交付时应按完整
快照范围保管产物。

## 运行方式

使用可信的本机 Ollama 服务，以 `OLLAMA_NO_CLOUD=1` 启动，并提前确认模型
已经安装。下例使用本次验证的端口，服务需在相应端口运行。CLI 接受明确的
回环 HTTP 地址和带 tag 的模型名。产物路径必须是新目录。

```powershell
.\venv\Scripts\python.exe -B -m rag_app.cli generate-eval-candidates `
  --snapshot-manifest storage/evaluation/corpus/p1-20261104-v2/corpus.manifest.json `
  --collection default --tenant-id default --permission-tags public `
  --output-dir storage/evaluation/candidates/review-run-02 `
  --endpoint http://127.0.0.1:45391 --model qwen3:4b-instruct-2507-q4_K_M `
  --seed 42 --max-batches 80
```

只审计语料时，使用 `--audit-only` 并省略模型参数。生成使用固定 seed 和参数，
按种子排列文档内的批次，记录模型 digest、提示词与代码哈希。相同快照、
配置和模型响应会得到字节一致的产物。真实推理还受 Ollama 版本、运行器和
硬件影响。

| 产物 | 内容 |
| --- | --- |
| `candidates.jsonl` | 逐条待审核候选、引用 ID、逐字引文、提议答案和范围 |
| `generation_manifest.json` | 模型、参数、seed、版本、范围、运行状态和文件哈希 |
| `candidate_quality_report.json` | 各类通过数、过滤原因和模型错误 |
| `coverage_gap_report.json` | 文档、Chunk、业务标签、解析状态、异常码证据与配额缺口 |

清单最后写入。缺少清单的目录表示该次写入未完成。模型失败时，命令保留
诊断产物并返回退出码 2。四种固定文件名均已加入 Git 和 Docker 忽略规则。

## 覆盖审计

- P0 schema v1 和 P1 schema v2 均通过 `load_corpus_snapshot` 校验，范围为
  `default/default/public`。P1 快照包含 3 份文档、447 个 Chunk，447 份正文
  哈希互异。与 P0 按 Chunk ID 比对，正文哈希一致。
- 源文档覆盖电信基础设施维护、智慧家庭装维职业技能、全光组网产品技术规范。
  元数据中有 6 个业务标签，分别为通用知识 220、设备维护 195、地址校验
  23、工单流转 5、异常处理 3、智能派单 1。计数来自导出标签，长尾类别
  的实际问题覆盖仍须人工确认。
- 所有 Chunk 的解析状态为 `parsed_with_warning`。其中 6 个有低文本量警告，
  5 个有高乱码率警告。表格、数值和单位类候选需要对照原文复核。
- 新快照中 447 个 Chunk 有 `error_codes` 数组，数组均为空，标量
  `error_code` 未出现。正文中符合明确标记和完整 token 规则的异常码为
  0 个。标准号可作为精确实体使用，异常码类别缺少真实证据。

## 代码审查

- 修复了缺少显式 `CorpusScope` 时可能绕过范围比较的路径。模型只能引用
  本次同文档、同 Chunk 标签批次中实际发送的片段，候选携带完整范围。
- 修复了将否定性异常码说明误当成证据和截取标准编号的问题。题面中
  编号在异常码标签之前或之后都会触发校验。异常码候选需要在完整 Chunk
  和引用片段中都能找到明确的整码证据。
- 模型预检要求已安装的本地 GGUF 和 digest，生成请求前后核对 digest。
  HTTP 客户端不使用代理或跟随重定向。回环客户端信任操作者配置的服务；
  本次运行由关闭云端功能的专用本机服务完成。
- 一次请求只分配一种题型。模型只能选择批次内片段 ID，引文由程序从
  快照原文回填。Ollama 结构化输出约束声明题型所需字段和引用数，程序仍
  独立校验返回内容。答案必须逐字出现在引文中，多条件与易混淆题还需至少
  两个不同 Chunk 和题面锚点。过滤重复、未知引用、未锚定答案和部分
  未获支持的题面标识。数值边界按完整 Chunk 检查，避免把 `50` 的一部分
  当成 `5`。非法模型字符会按条拒绝并计数。
- 自动过滤覆盖可机械检查的条件。问题与答案是否真正匹配、跨段证据是否
  支持组合条件、近义重复和解析保真度留给人工审核。候选数量只衡量生成
  产量，50 条高质量 Gold 的可行性仍取决于人工筛选与异常码补源。
