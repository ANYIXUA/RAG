# P7 历史指标定义与独立复算

状态：`AUDIT_PREPARED`；人工状态：`HUMAN_REVIEW_PENDING`。以下是历史 Silver 自动评审的算术和证据链审计，AI 判断不等于人工签核。没有新增模型调用，没有把自动正确率认定为人工准确率或正式 Gold。

## 数据来源和复算边界

输入目录为 `p6-silver-e2e-500/runs/p6-e2e-run-01-qwen-flash/`，冻结题目来自 `p6-silver-e2e-500/silver_cases_500.jsonl`。`cases/*.json` 是执行记录；`answers.jsonl` 是回答投影；`traces.jsonl` 是完整执行投影；`scores/*.json` 保存原评分，`scores_recovered/*.json` 保存复用已付费响应恢复的评分。

合并顺序为先 `scores`、再按相同 `case_id` 叠加 `scores_recovered`，与历史 `e2e_run01.py::load_scores` 一致。原始评分 500 条中 18 条失败，8 条恢复，因此有效评分为 490 条，最终失败 10 条。恢复不会增加题数或覆盖原始失败文件。独立复算验证了 500 个 case_id 对齐、回答内容一致、case/trace 全对象一致、合并评分与 `scores.jsonl` 一致。

`recalculate_metrics.py` 仅使用 Python 标准库；不导入历史运行器，不执行历史报告器，不连接模型、数据库或外部网络。所有写入只落在 P7 目录。历史代码仅阅读用于核对规则。`metrics_source_hashes.json` 留存本脚本读取的历史证据哈希。

可复现命令（项目根目录执行）：

```powershell
venv/Scripts/python.exe -B p7-rag-final-audit-01/recalculate_metrics.py
```

## 核心结果与分母

| 指标 | 独立复算 | 分母定义与含义 |
|---|---:|---|
| 执行完成 | 500/500 = 100% | 500 个唯一 Silver case 的最终执行状态 success；不表示答案正确 |
| 评分成功 | 490/500 = 98% | 合并后 score_state=success；与执行成功分开 |
| Silver 满分回答比例 | 423/439 = 96.355353% | 排除下述 61 题后，answer_correctness.score=1；不是 423/500，也不是人工准确率 |
| Faithfulness 均分 | 474.5/489 = 0.9703476483 | 490 个成功评分中排除 p6s-0310 的 null；满分472/489 |
| 完整度均分 | 468.5/488 = 0.9600409836 | 490 个成功评分中排除 p6s-0310、p6s-0381 的 null；满分453/488 |
| 疑似幻觉 | 18/490 = 3.673469% | 成功评分中 hallucination_suspected=true；失败评分 raw 中的标记不并入已接受评分 |
| 无效引用题数 | 6/500 = 1.2% | 答案至少一处 [n] 或【n】编号不在 sources 的1起始范围内 |
| 不能可靠判断主桶 | 20/500 = 4% | 历史代理诊断的优先级结果；不等于20次评分调用失败 |
| 多条件满分回答 | 89/95 = 93.684211% | 100个多条件题中5个评分失败；与多条件完整度90/95不同 |
| 暂定无答案行为满分 | 27/36 = 75% | 50个unanswerable候选中36个非null；14个null不当作0分或成功 |

所有指标的完整 `case_id` 成员在 `metrics_recalculation.json` 对应的 `denominator_case_ids`、`numerator_case_ids` 中，分母不是仅凭汇总数字推断。分数均分保留0、0.5、1，不把0.5算成满分。null独立列出。

### 500 → 439 的互斥排除

按以下优先级分配唯一排除理由，`correctness_exclusions.reasons` 给出全部成员：

1. 50 条未经人工核验的 unanswerable 标签；整个类型不进入 Silver 正确性分母。
2. 1 条来源解析歧义：`p6s-0473`。其正确性 null 是历史归一化强制覆盖，不是 Judge 判错。
3. 10 条评分失败：`p6s-0023, p6s-0037, p6s-0041, p6s-0053, p6s-0157, p6s-0195, p6s-0230, p6s-0389, p6s-0420, p6s-0454`。

本批不存在另外的执行失败、普通题成功评分后正确性null或其他排除：`500 − 50 − 1 − 10 = 439`。这三组实际无交集，既没有双重扣减，也没有把评分失败自动记为答案错误。

### 20 个不能可靠判断的来源

互斥拆分为评分失败10、低置信度1（p6s-0265）、来源歧义1（p6s-0473）、暂定无答案规则8（p6s-0236、0237、0243、0255、0256、0266、0364、0458）。最后8题的规则是：unanswerable、拒答行为为0或0.5、没有疑似幻觉标志且faithfulness不为0。它是在尚未人工确认无答案标签时的保守分类，不是新的人工裁决。

## 错误类型为什么不能相加

历史主分类按执行失败 → 评分失败/低置信度/0473 → 暂定拒答不确定 → 未召回参考证据 → 参考证据未完整进入提示词 → 幻觉/faithfulness=0 → 引用问题 → 不完整 → 答错 → 未发现上述失败的顺序，首次命中即停止。独立复现得：检索参考证据未命中7、上下文参考证据未完整进入1、证据在但答错0、不完整15、无支撑生成10、引用不匹配10、执行失败0、不能可靠判断20、未发现上述失败437，总计500。

因此“18个疑似幻觉标志”不等于“10个无支撑生成主桶”；“6个无效引用题”不等于“10个引用主桶”，也不等于“20个引用语义评分非满分”。主桶反映优先级，标志反映可重叠维度。

| 相交集合 | 数量 | case_id |
|---|---:|---|
| 疑似幻觉 ∩ 无效引用 | 1 | p6s-0310 |
| 疑似幻觉 ∩ 不能可靠判断 | 1 | p6s-0265 |
| 无效引用 ∩ 评分失败 | 1 | p6s-0037 |
| 无效引用 ∩ 不能可靠判断 | 3 | p6s-0037、0237、0243 |
| 疑似幻觉 ∩ unanswerable | 4 | p6s-0265、0310、0312、0434 |
| 无效引用 ∩ unanswerable | 3 | p6s-0237、0243、0310 |

完整两两交集（含空集合）见 JSON 的 `error_pairwise_overlap`。疑似幻觉、无效引用、评分失败、低置信度、0473歧义、全部unanswerable六组并集为77题；这77题只是指定风险覆盖集合，不是77个已确认错误。

引用按每次标记出现计数：共2606次，编号有效2590次，16次编号无效分布在6题；编号有效且来源规范化文本前35字符出现在实际prompt中的2582次。这个文本前缀检查只是历史代理条件，不能推出引用语义正确。无效编号6题为p6s-0037、0088、0237、0243、0247、0310；来源前缀检查不通过的题数为10。

## 延迟口径

只取500个最终成功尝试，每题一次，不包含Judge耗时。墙钟耗时是 `wall_seconds×1000`，包含观测、持久化及生产查询日志；生产trace是另一计时边界，不能混写。

| 毫秒 | 均值 | p50 | p95 |
|---|---:|---:|---:|
| 最终成功尝试墙钟 | 2236.1446069907 | 2204.9754000036 | 2879.0612699813 |
| 生产trace总计 | 2205.446574 | 2176.0305 | 2834.44575 |
| 检索 | 787.34997 | 725.2895 | 1298.01305 |
| 生成 | 1408.275012 | 1398.13 | 1782.4042 |

分位数使用排序后零基索引 `(n−1)×p` 的线性插值，p分别为0.5和0.95。各阶段分位数不能相加推导总时延；其他阶段完整值和成员在JSON。八组延迟与历史汇总按浮点容差一致。

## 历史40条抽查清单的真实选择依据

独立复现 `e2e_run01_report.py::make_human_checklist` 后，40条成员及顺序与历史JSONL完全一致。脚本先强制加入p6s-0473及p6s-0088，再按exact_fact、procedure、multi_condition、colloquial、unanswerable顺序，各类型补足8条。每类候选按 `needs_human_review` 优先、主桶不是pass优先、case_id字典序排序；不是随机抽样，也不保证覆盖所有风险。

覆盖情况：评分失败10/10、疑似幻觉7/18、无效引用5/6、不能可靠判断18/20、unanswerable8/50。无效引用漏覆盖p6s-0310；不能可靠判断漏覆盖p6s-0364和0458。不能由这40条推算总体准确率或声称全部风险已人工复核。

历史人工审核字段全部为空。JSON中 `historical_spot_check_40` 保存完整历史顺序、逐题入选原因、各风险集合的已覆盖与未覆盖成员。
